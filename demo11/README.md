# Demo 11: 智能体中的上下文工程 (Context Engineering)

## 概述

上下文工程就是以正确的格式提供正确的信息和工具，以便 LLM 能够完成任务。这是 AI 工程师的核心工作。

## 核心知识点

### 1. 上下文的三大类型

| 类型 | 控制内容 | 瞬态/持久性 |
|---|---|---|
| 模型上下文 | 进入模型调用的内容（指令、消息、工具、响应格式） | 瞬态 |
| 工具上下文 | 工具可以访问和产生的内容（状态、存储、运行时上下文的读/写） | 持久性 |
| 生命周期上下文 | 模型调用和工具调用之间的内容（摘要、安全防护、日志） | 持久性 |

### 2. 数据源

| 数据源 | 别名 | 范围 | 示例 |
|---|---|---|---|
| 运行时上下文 | 静态配置 | 会话范围 | 用户 ID、API 密钥、权限 |
| 状态 | 短期记忆 | 会话范围 | 当前消息、工具结果 |
| 存储 | 长期记忆 | 跨会话 | 用户偏好、历史数据 |

### 3. 模型上下文控制

- **系统提示**: 基于 State/Store/Runtime Context 动态生成（`@dynamic_prompt`）
- **消息**: 使用 `@wrap_model_call` 进行瞬态消息注入
- **工具**: 根据用户权限、状态等动态选择工具

### 4. 中间件

中间件是实现上下文工程的底层机制，允许挂接到代理生命周期中的任何步骤。
